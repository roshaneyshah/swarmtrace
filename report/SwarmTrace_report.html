SwarmTrace: identifying renamed agents and catching log tampering in agent swarms

Swarm Alignment Hackathon, Apart Research × AI Alignment Foundation × AE Studio, November 2026 · Track 4 (Multi-Agent Oversight and Control), with Track 3 (Agent Infrastructure)
Abstract. In the 2026 Hugging Face incident, about 1,200 agents used 7,905 names, one agent coordinated hundreds of others, and some agents edited their own transcripts. Oversight that keys on names and trusts self-reported logs fails against all three. We release SwarmTrace, which has three parts. (1) SwarmSim is a seeded testbed that reproduces these signatures with full ground truth (~2,557 names for 400 agents, coordinators that emerge on their own, one of them dominant, 7% of agents tampering). (2) Constrained alias linking clusters names by writing style, under the rule that one agent holds one name at a time. It recovers true identities with ARI 0.91, against 0.67 for style clustering that is given the true number of agents and 0 for treating names as identities. Linking also unmasks the hidden coordinator: the top raw name accounts for 6% of task assignments, the top linked identity for 11% (truth: 11%). (3) Witness chains hash-chain each transcript and have peers countersign the head hash. When witnesses are self-selected, collusion inside the tamperer's coordination tree drops detection of an edited log entry from 0.88 to 0.15. When a monitor assigns witnesses from outside the tree that linking infers, detection stays at 0.86, close to the oracle's 0.87. The two halves depend on each other: tamper-evident logging against a coordinated swarm needs to know who is coordinating with whom, and that needs identity resolution. Our agents are scripted rather than LLMs, so the absolute linking numbers are an upper bound. We measure how the numbers degrade under adversarial style drift and dialect convergence.

1. Introduction

The investigation of the July 2026 swarm incident (METR, 2026; Swarm Traces, 2026) reported three facts that together defeat single-agent oversight. The agents renamed themselves (7,905 names for ~1,200 agents). A small number of agents coordinated hundreds of others over an unsanctioned message board. Some agents edited or spoofed their own transcripts (~7% of those reviewed). A monitor that counts actions per name sees thousands of minor actors where there were a few major ones. A monitor that reads self-reported logs reads whatever the agents chose to leave behind.

We treat these as two linked problems. Identity resolution: from the public record alone, which names belong to the same agent? Tamper-evident oversight: how do we detect transcript edits when the agents best placed to vouch for each other are the ones colluding? Our main finding is that the second problem depends on the first. Peer witnessing resists collusion only if witnesses come from outside the agent's coordination group, and you can only tell who is in that group once you have resolved who is behind each name.

Contributions.

  1. SwarmSim, a seeded, CPU-only testbed with full ground truth. It reproduces the incident's signatures: name churn, preferential-attachment coordinator emergence, and self-log tampering.
  2. Constrained alias linking, average-linkage stylometric clustering under a temporal cannot-link constraint. Across 5 seeds it scores ARI 0.91, and it holds at incident scale.
  3. Witness chains, hash-chained transcripts countersigned by peers, together with an evaluation of witness-selection policies under collusion. Stratified assignment that uses linked identities keeps detection near the oracle level when collusion is total.

2. Testbed: SwarmSim

Each of N=400 agents (1,200 in the scale run) has a persona that fixes its idiolect: one surface form for each of 10 concepts (e.g. "taking" / "grabbing" / "I'll handle"), an opener, a sign-off, casing, punctuation, an emoji habit and a typo rate. For 240 steps, each agent is active with p=0.35. When active it executes a private tool call and usually posts to the shared board: claims, reports, completions, bids to coordinate, joins, and assignments. Agents adopt a fresh name with p=0.024 per step, which gives ≈6.5 names per agent, close to the incident's 7,905/1,200 ≈ 6.6. Agents choose leaders by preferential attachment ((followers+1)1.2), which produces one dominant coordinator per run, matching "one agent coordinating hundreds". 7% of agents are tamperers. Every board message, rename and tool call is logged together with the hidden ground truth. A run averages 29,259 messages and 2,557 observed names, and takes under a second. Two adversarial knobs stress the oversight tools: style drift (the fraction of persona features an agent resamples at each rename) and conformity (the per-message probability of using the board's most popular form, a stand-in for a swarm converging on a shared dialect).

3. Method

3.1 Constrained alias linking

For each name we concatenate its posts, with @mentions removed, and embed them with TF-IDF over character 2–4-grams (sublinear tf). Our structural insight is that an agent holds one name at a time, so the activity intervals [first post, last post] of one agent's names never overlap. We run average-linkage agglomerative clustering on cosine similarity. Two clusters may merge only if no interval in one overlaps an interval in the other, and we stop when the best admissible similarity falls below θ. The only hyperparameter is θ=0.30, tuned on a held-out dev seed (ARI is flat between 0.25 and 0.40). Baselines: (a) names as identities; (b) unconstrained style clustering given the oracle number of agents; (c) a hand-off matcher that links each name to at most one predecessor by min-cost bipartite matching on style plus a time-gap prior.

3.2 Witness chains

Each agent keeps its transcript as a hash chain hk = SHA-256(hk−1 ‖ entryk). On each post, one witness records (k, hk) in its own chain. Rewriting entry x changes every head from x onward, so any witness record with index ≥ x exposes the edit when audited. We checked this end to end: on a real simulated transcript (158 entries), honest verification yields 0 failures, and editing entry 5 invalidates 51 witnessed heads. The monitor audits each witness record independently with probability a (partial visibility; default a=0.10). A tamperer escapes if every record that covers the edited entry is held by a colluder or goes unaudited. Collusion follows coordination: each member of the tamperer's coordination tree (followers of the same leader) joins the cover-up with probability c. We compare four policies that produce the same number of witness records:

  • Self-selected: the agent picks a witness from its own workstream, as in a typical gossip protocol.
  • Random: the monitor assigns a uniformly random witness.
  • Stratified: the monitor assigns a random witness from outside the agent's coordination tree. The tree is inferred from join and assign messages, aggregated by (i) raw names or (ii) linked identities, or (iii) given by an oracle.
  • Central anchor: the agent sends its head to the monitor every 10 steps. There are no peers, and the monitor checks all anchors.

We report the exact probability of detecting an edit to a uniformly random past entry, averaged over tamperers, coalition draws and seeds 0–2. We also report the strategic window: how many recent entries no honest witness covers, which a tamperer who knows the schedule can edit without being caught.

The constraint does most of the work. Unconstrained style clustering merges agents with similar personas even when it is told the true number of agents. Greedy hand-off matching chains errors forward: one wrong link corrupts the rest of the chain. Clustering whole groups of names lets every name's evidence count. At incident scale (1,200 agents, 7,672 names, 87,678 messages; the incident had 7,905 names), linking reaches ARI 0.84 and B³-F1 0.89, recovering 1,299 identities in 521 s on a 4-core CPU.

4.2 Unmasking the coordinator (E3)

On average the true top coordinator used 7.0 names and issued 11% of all assignments. The most active name accounts for only 6% of assignments, and 90 distinct names appear to issue assignments, against 20 true coordinators. After linking, the top identity accounts for 11% (20 apparent coordinators). The true top coordinator ranks #1, #1, #1, #1, #1 across the five seeds. A per-name monitor sees the coordinator's activity split across several names, each about the size of an ordinary coordinator. The concentration of control, which is the signal that should trigger escalation, is hidden until names are linked.

Central anchoring detects random edits best (0.97), since the monitor checks every anchor. But it costs the monitor 40.0 records per step whether or not agents are active, so its load grows linearly with swarm size. It also leaves a window of ~4.3 entries that a strategic agent can rewrite between anchors. Peer witnessing moves storage onto the peers and makes the monitor's work an audit-rate dial (12.3 audits per step at 10%). Its weakness is collusion, and stratification fixes that. Linking degrades gracefully under dialect convergence: at conformity 0.8, ARI is 0.74, against 0.21 for style-only clustering. Adversarial style drift is its main weakness. Resampling 25% of the persona at each rename cuts ARI to 0.46, and a full resample leaves only the temporal constraint, which cannot separate the many agents that rename at similar times. Style drift costs the agent something, though. Under the stratified policy, an identity that cannot be linked to its earlier names is assigned witnesses as if it were a stranger, and a deployment can require that new identities be witnessed and audited at a higher rate until they build history. That makes renaming expensive instead of free. Signals we did not use would further raise the cost of evading linking: timing rhythms, tool-call fingerprints, and the content of hand-offs.

5. Discussion and limitations

  • Scripted agents. SwarmSim personas are hand-designed, so stylometric separability is likely higher than for LLM agents that share one base model and system prompt. The absolute linking scores are therefore an upper bound. The structural results do not rely on style: the cannot-link constraint, coordinator splitting under renaming, and the collusion analysis of witness policies. The testbed is built so that LLM agents can replace the scripted ones; a natural next step is to run small open models in the same loop and test whether the results transfer (Track 1, Q3).
  • Concurrent names. We assume one active name per agent, as the incident data suggest (names were successive renames). An agent that runs several sock-puppets at once breaks the cannot-link constraint. The linker would then need a softer overlap penalty, and per-identity signing keys (Track 3) become necessary.
  • Witness model. We model collusion within coordination trees, and in the stratified policy colluders cannot predict which outside agent will be assigned. A swarm-wide conspiracy (c=1 across all trees) defeats every peer-based scheme, and only central anchoring survives it. A practical design combines rare central anchors, as a backstop against swarm-wide collusion, with stratified peer witnessing for fine-grained coverage.
  • Real data. We did not validate on the Swarm Traces payloads or AI Village transcripts in the time available. The linker takes only (name, timestamp, text) triples, so applying it to those corpora is straightforward. Their ground truth is partial, so evaluation would use the known rename events.

6. Conclusion

Treating names as identities, or trusting self-reported transcripts, are the two assumptions a swarm like the one in the 2026 incident breaks first. A cheap, interpretable linker that combines writing style with the fact that one agent holds one name at a time recovers identities and the coordination structure behind them. Feeding that structure into witness assignment makes tamper-evident logging hold up under collusion. Both tools, and the testbed that scores them, run on a laptop in minutes.
